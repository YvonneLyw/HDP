# 项目导读：从 HDP 到几何与视觉双分支

这份说明帮助你先了解项目的研究思路，再找到论文和代码的阅读入口。第一次看时，抓住 **HDP 分层框架 → 几何/视觉双分支 → 候选动作选择** 这条主线即可。

## 1. 这个项目想解决什么问题

项目研究的是机器人操作：机器人根据观测，生成接近、抓取和移动物体等动作。这里的策略主要从已有示范数据中学习，使用扩散模型生成一段动作序列，再执行其中一部分，根据新观测继续预测。

我们关心的是：**当机器人看到的信息不够准确，或者遇到与示范不同的状态时，怎样让它仍然生成和选择相对可靠的动作？**

例如，物体位姿估计不准时，依赖位姿和点云的动作可能受影响，而图像里仍可能保留有用的信息；反过来，图像也可能受到遮挡。因此，本项目尝试让不同观测条件产生各自的动作候选，再判断当前更适合采用哪一个。不同信息是否真正互补、选择是否有效，是这条研究路线关注的问题。

## 2. 基础框架：原版 HDP 在做什么

本项目基于 [Hierarchical Diffusion Policy: Manipulation Trajectory Generation via Contact Guidance](https://arxiv.org/abs/2411.12982)。HDP 把操作过程分成接触子目标预测与动作生成两个层次。

| 模块 | 在框架中的作用 | 直观理解 |
| --- | --- | --- |
| Guider | 根据观测预测接触子目标（subgoal） | 下一步希望在哪里建立怎样的接触 |
| Actor | 根据观测和 subgoal 生成动作序列 | 为达到这个接触目标，机器人应该怎样运动 |
| Critic | 估计动作的价值，并为 Actor 的学习提供信号 | 这个动作对目标是否有帮助 |

基本执行流程是：**观测 → Guider 预测 subgoal → Actor 生成动作 → 执行 → 获取新观测**。Critic 参与训练中的价值评估；它的角色与前两个模块不同，不必把三个模块理解为每次执行都依次经过的三个网络。

先理解这个框架，再看本项目的改动，会容易得多。

## 3. 本项目的核心改动：让低层 Actor 有两种观测条件

我们保留 HDP 的高层接触引导，在低层引入几何与视觉两条条件路径。这个设计借鉴了 [D3P](https://arxiv.org/abs/2511.00555) 中不同观测组合、双分支和视觉时序表示的思路，并接入 HDP 框架。

| 路径 | 主要使用的信息 | 希望利用的特点 |
| --- | --- | --- |
| A：几何/状态分支 | 物体与机器人状态、可选的点云，以及 subgoal | 显式的空间位置、姿态与接触关系 |
| B：视觉分支，先以代码中的 B2 理解 | 两个视角的 RGB 图像、机器人关节/夹爪状态，以及 subgoal | 图像中的场景信息与机器人自身状态 |

A、B **共用一个扩散 Actor**，使用不同条件生成同一动作空间中的候选动作。两路也共享 Guider 给出的 subgoal。

```text
                         Guider
                            ↓
                       共享 subgoal
                        ↙         ↘
              几何/状态条件       视觉/机器人状态条件
                   ↓                    ↓
             同一个 Actor            同一个 Actor
                   ↓                    ↓
                A 候选动作          B 候选动作
                        ↘         ↙
                         候选选择
                            ↓
                     执行一段，再观察
```

视觉分支还包含 DKO（Deep Koopman Operator）相关辅助学习，用来约束视觉特征在时间上的变化。第一次阅读只需知道它服务于视觉表示学习，具体公式可以后看。代码里还保留了 B1 这种使用 DKO latent action 的条件变体；先理解 A/B2，就能抓住主要结构。

## 4. 有了两个候选，为什么还要研究 DOSER

两个分支可能给出不同的动作，接下来就需要回答：**当前应该相信哪一个？** 这也是生成候选之后一个独立的研究问题。

仓库保留了几种判断思路：用扩散模型的重构误差衡量候选是否符合模型；用 Critic 的 Q 值衡量动作价值；以及借鉴 DOSER，同时考虑数据支持度和后继状态的价值。

[DOSER](https://openreview.net/forum?id=a4DbIONcpb) 为这里提供了处理分布外动作的思路。直观地说，一个动作不太像训练数据里的动作，并不能直接说明它一定无用，还可以进一步考虑它可能把机器人带到怎样的状态。本项目把这种思路改造成 A/B 候选的选择机制，具体决策随所选模式而变化。

阅读代码时先认识三个名称即可：

- `doser_err`：主要比较两个候选在独立动作检测器中的评分。
- `doser_gt`：在显式状态空间中学习后继预测，再结合支持度和价值进行选择。
- `doser_latent`：在学习到的隐空间中做后继预测与评估。

这里的 `latent` 可以理解为网络压缩得到的状态表示。它是否保留了足够信息、预测与评分是否可靠，是仍需研究的部分。`gt` 版本也需要学习预测，并不是直接知道未来会发生什么。

这几个名称是候选选择方法；A/B 才是产生动作候选的条件分支。先分清这两层，很多开关就不容易混在一起。

## 5. 当前仓库为什么会有这么多模式

仓库记录了项目逐步发展的过程：原版 HDP、几何/视觉融合、不同选择方法，以及动作执行阶段的改进尝试。它们用于研究不同问题，不需要在第一次阅读时全部展开。

可以把现有代码按以下关系理解：

| 层次 | 相关内容 |
| --- | --- |
| 基础框架 | HDP 的 Guider、Actor、Critic |
| 候选生成 | A/B 条件、共享 Actor、视觉编码与 DKO |
| 候选选择 | 误差、Q、DOSER 等评分与选择方式 |
| 后续扩展 | 时序聚合、动作平滑、QGF、Best-of-N 等生成或执行改进 |

`SINGLE` 表示使用指定分支；`SWITCH` 在训练时轮流使用不同分支，在推理时生成两路候选并选择。具体选择依据由另一个设置决定。先理解这些模式所处的层次，参数值和组合规则等真正读到相应实现时再查。

当前已有融合和选择机制的实现，也开展过仿真比较；扰动条件下能否可靠地利用分支互补、DOSER latent 是否足够可靠，以及如何迁移到实机，仍有待进一步验证和完善。因此，应把它看作一份持续发展的研究代码。

## 6. 建议怎样入手

**先看原版 HDP，再看本项目增加的两部分：分支条件与候选选择。** 理论基础不熟时，可以先理解输入、输出和模块关系，再补训练目标与推导。

| 阅读顺序 | 看什么 | 先抓住的问题 |
| --- | --- | --- |
| 1. 原版 HDP | [论文](https://arxiv.org/abs/2411.12982)的框架图、方法概览，以及[作者仓库](https://github.com/dexin-wang/Hierarchical-Diffusion-Policy) | subgoal 是什么？Guider、Actor、Critic 分别负责什么？ |
| 2. 本项目的融合部分 | 下方两份主要 policy 文件，结合本导读的 A/B 图 | 与原版相比，Actor 的条件输入怎样改变了？ |
| 3. D3P 的相关思路 | [论文](https://arxiv.org/abs/2511.00555)中双分支与 DKO 部分 | 为什么考虑不同观测组合？为什么约束视觉特征的时序关系？ |
| 4. 候选选择 | DOSER 的基本思路，再看本地 selector | 生成了两个候选之后，依据什么选择？ |

第一次阅读可以暂时略过复杂 loss 推导、全部选择器变体、QGF 和具体调参。你可以先带着一个贯穿始终的问题看代码：**一份观测是怎样变成最终执行的那段动作的？**
